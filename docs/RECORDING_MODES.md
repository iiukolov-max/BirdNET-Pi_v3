# Recording modes (unreleased candidate)

## Service launch permissions

Basic Settings has a separate **Services** block below **Model**, with Service and Allow columns. Unchecking a service stops it when settings are saved and prevents subsequent starts, including direct systemctl commands, automatic restarts, mode changes and boot. Live audio controls both the stream worker and Icecast. Statistics, daily charts, the spectrogram viewer, log viewer and web terminal have independent permissions. The selected mode is an additional restriction: Economy keeps these additional services off even when their permissions are checked. Returning to Normal starts only the permitted services.

Recording and both automatic/manual BirdNET analyzers are excluded from the permissions table. Normal runs recording and automatic analysis. Economy boots into recording only; manual analysis pauses recording and restores it afterwards. Caddy/PHP and the mode, CPU and startup-log infrastructure remain available.

Every managed unit uses a systemd ExecCondition to read the current configuration before executing the service. Denied starts are skipped rather than treated as service crashes. Settings use the existing transaction and lock; failures restore the prior configuration. Unit restoration also respects the current permissions. The installer/updater installs these conditions through install_recording_modes.sh.

Fresh installations default to all six permissions checked, Normal, full BirdNET V3 preview3.1 and Geomodel V3.0.4. Both geomodel files are pinned by size and SHA256 in the model manifest and downloaded by the existing installer. Existing configuration files are not replaced by these defaults.

Basic Settings → Recording mode selects:

- **Normal:** the existing WAV capture, inference, deletion of recordings without detections and extraction of detection clips. The existing Extractions Audio Format setting still controls those clips.
- **Record only (economy):** retain complete microphone audio in `BirdSongs/Archive`, without automatic analysis. PCM goes directly into a per-file encoder; no intermediate WAV is written to the card. FLAC/WAV preserve the original samples; MP3, Ogg and Opus are lossy.

Both modes use **Recording Length** and **Extractions Audio Format** in Advanced Settings (`RECORDING_LENGTH` and `AUDIOFMT`). There are no separate archive length/format settings. Economy supports FLAC, MP3, Ogg, Opus and WAV. Recording continues through a bounded memory buffer (at most 16 MiB) while the previous encoder closes. Capture has higher scheduling priority than manual inference. Files are published only after their encoder finishes. Graceful stop finalizes the last short segment. Abrupt power loss can leave an unfinished file in `.partial`; it is preserved and logged for recovery.

Cleanup has one setting: maximum disk usage, 85% by default (15% free). Internal batches contain at most 100 oldest files and repeat until usage is at or below that limit. The free-space reserve is at least 512 MiB when starting cleanup and 1 GiB when finishing. Each batch is followed by another free-space check. Only completed recorder-named files in the dedicated archive are eligible; active files, symlinks, detection clips, database and system files are excluded. If the reserve cannot be restored, recording stops with an error instead of filling the filesystem.

Mode, format, segment length and cleanup settings persist across reboot. Basic Settings switches use rollback on startup failure; mode changes restart capture and cause a short gap. Economy checks and disables additional BirdNET services at boot and on entry; returning to Normal restores their saved states. Caddy/PHP stay available. Archive capture supports the microphone input; RTSP remains available in Normal.

The Overview page shows an **Analyze files** button in a separate block on the right, only in economy. It is enabled only when analysis is idle and unprocessed files exist; it is disabled while running, when empty or when status is unavailable. Labels follow Database Language. The block separates all waiting files, remaining files in the current job and newly recorded files. It shows progress, measured files/minute, estimated finish time, free space and approximate recordings/days before cleanup. These are capacity estimates based on the measured encoding rate; recording continues in a loop after cleanup. The estimate appears after the first successful file and is approximate. Each launch gracefully stops microphone recording, finalizes the current short segment, and processes the completed files then present. No new audio is captured during manual analysis. Previously active recording resumes automatically after completion, error or cancellation; systemd also restores it if the analyzer is killed. If recording was already stopped, it remains stopped. A mode change is handled by the settings transaction instead of restarting the old recorder. The panel explains when recording is paused. Repeated clicks do not create another analyzer. Switching to Normal stops manual analysis. On every economy-mode boot, the guard enables/starts recording and stops both automatic and manual analysis; a pre-reboot manual run and its recording pause are not resumed.

Successful files are tracked by name, size and modification time in the same SQLite transaction as their detections and skipped on later runs. Failures remain eligible for retry. Successful source recordings are removed only after the detections/completion transaction commits and the original file fingerprint is rechecked. Failed files remain for retry. Disk cleanup may remove unprocessed files when space runs out. An opened file stays readable if cleanup unlinks it; files removed before opening are reported as missing. Detection extraction uses each file's actual duration even after Recording Length changes.

Validated on the Trixie test card: both mode transitions, real microphone FLAC, five codec formats on synthetic audio, lossless PCM equivalence for FLAC/WAV, oldest-100 cleanup in an isolated fixture, invalid cleanup rejection and switch rollback. Full clean installation/upgrade and long-term disk-fill testing remain separate checks. This candidate has not been published to GitHub.

Basic and Advanced Settings enqueue background jobs and show their completion or error. Unchanged settings do not restart services. Relevant changes restart only affected services that were already active; entering Normal intentionally restores automatic analysis. Caddy/PHP remain available.

Additional checks: 13 switch/rollback/selective-restart tests; real Basic/Advanced HTTP saves preserved service states; 36 language catalogs; four browser button states; cleanup through two batches; actual-duration extraction, failed-file retries and duplicate protection. A 7-second encoder stall with 60 seconds queued audio preserved bit-exact PCM. Latest changes were not cold-boot tested or measured with a wattmeter.
# Automatic economy CPU profiles

Economy recording uses CPU 0 for the recorder and its children, one FFmpeg encoder thread, and the lowest supported frequency (600 MHz on the tested Pi Zero 2 W). Capture and buffer threads remain separate to preserve audio; restricting a CPU does not mean removing those I/O threads. Other CPUs remain online for system services.

Manual analysis restores the recorder CPU mask, keeps two V3 inference threads, and permits frequencies up to the original system limit. A root controller checks temperature every two seconds: at 78°C or an active firmware frequency/throttle flag it reduces the cap by one supported step; after 30 seconds at or below 74°C it raises the cap by one step. This is a feedback policy, not a guarantee that hardware throttling can never occur, particularly when starting hot.

Normal mode, idle, and controller shutdown restore original frequency limits, governor and recorder CPU mask. The controller starts at boot and is retained by the economy service guard. Current profile is recorded in /run/birdnet-cpu-policy.json. Disable and stop birdnet-cpu-policy.service to restore the original runtime policy. The full acoustic model and recording format are unchanged.
